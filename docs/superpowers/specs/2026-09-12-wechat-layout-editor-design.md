# WeavePress 微信排版编辑器设计

## 目标

在现有“微信稿件 → 审核 → 微信公众号草稿箱”链路中加入可视化排版能力，形成：

`采集文章 → AI 改写/人工建稿 → 可视化排版 → 手机预览 → 保存版本 → 审核 → 写入公众号草稿箱`

首版采用整篇统一主题和三栏专业工作台。编辑者不再直接维护正文 HTML，而是编辑结构化文档；服务端使用内置主题生成微信公众号兼容的内联样式 HTML，并继续复用现有版本、预检、审核和发布能力。

## 已确认范围

### 本轮实现

- TipTap 结构化富文本编辑器。
- 三栏工作台：左侧主题与素材，中间正文编辑，右侧微信手机预览。
- 标题、段落、粗体、斜体、下划线、二三级标题、引用、有序/无序列表、分割线、链接和图片节点。
- 六套内置整篇主题：极简商务、清爽蓝、自然绿、暖生活、雅致中国风、活力品牌。
- 原文图片和本地上传图片统一进入稿件素材库。
- 图片插入、拖动排序、50%/75%/100% 宽度、居中、替代文本和图片说明。
- 手动保存、未保存提示、历史版本恢复和并发版本冲突处理。
- 旧 HTML 稿件首次编辑时转换为结构化文档。
- 服务端结构校验、微信 HTML 渲染、现有预检和发布适配。
- 桌面端完整三栏；较窄屏幕把左侧素材和右侧预览折叠为抽屉。

### 本轮不实现

- 主题后台管理、用户自定义 CSS、主题市场。
- 单个内容块自由切换复杂样式。
- 多人实时协同、自动云端保存。
- 图片裁剪、滤镜、拼图、水印和 OCR。
- 素材删除、跨稿件素材库、外部图片 URL 直接插入。
- 微信群发；仍只写入微信公众号草稿箱。

## 产品与交互设计

现有稿件详情页改造为三栏工作台，不增加孤立的排版页面。

### 顶部区域

- 展示稿件状态、版本号、来源文章和更新时间。
- 提供返回、查看来源、版本记录、发布前检查、保存新版本、提交审核、审核和写入草稿箱操作。
- 只有 `editing` 状态允许修改结构化正文、主题、图片和元信息。
- 页面存在未保存修改时展示明确状态；关闭页面或切换路由时二次确认。

### 左栏：主题与素材

- “主题”页签展示六套主题缩略预览，点击后立即更新中间画布和右侧手机预览。
- 切换主题只修改 `themeId`，不改变正文节点及顺序。
- “素材”页签合并展示来源文章图片和本稿新上传图片，并标记来源、尺寸、文件大小及封面状态。
- 支持上传新图片、插入当前光标位置和设为封面。
- 本轮不提供删除按钮，避免历史版本引用的素材失效。

### 中栏：结构化编辑器

- 使用 TipTap Vue 3 编辑器，基础扩展采用 StarterKit，并增加图片、链接、下划线和占位提示扩展。
- 工具栏只暴露首版允许的节点与格式。
- 图片是独立块节点，可拖动排序；属性只允许 `draftAssetId`、`width`、`align`、`alt` 和 `caption`。
- 粘贴 HTML 时只保留支持的语义节点和文本格式；外部样式、脚本、事件属性及外链图片全部移除。
- 从编辑器复制内容时输出当前主题渲染后的安全 HTML，便于人工兜底使用。

### 右栏：微信预览

- 模拟微信公众号手机正文宽度，实时显示当前标题、作者、摘要、封面和正文。
- 编辑中的即时预览由前端使用主题定义渲染；保存后以服务端返回的 `previewHtml` 为准。
- 预览 iframe 使用 `sandbox` 和限制性 CSP，不执行稿件脚本。
- 显示微信标题、作者、摘要和图片限制提示；正式是否可发布仍以服务端预检为准。

## 结构化文档协议

`editorDocument` 使用受限的 TipTap/ProseMirror JSON 结构，根节点固定为 `doc`。允许节点：

- `paragraph`
- `heading`，只允许 level 2 或 3
- `blockquote`
- `bulletList`、`orderedList`、`listItem`
- `horizontalRule`
- `text`
- `image`
- `hardBreak`

允许 mark：`bold`、`italic`、`underline`、`link`。链接只允许 HTTP/HTTPS，发布 HTML 固定增加安全属性。文本、替代文本和说明统一转义。

图片节点示例：

```json
{
  "type": "image",
  "attrs": {
    "draftAssetId": 18,
    "width": 75,
    "align": "center",
    "alt": "产品展示",
    "caption": "图片说明"
  }
}
```

服务端设置文档总节点数、嵌套深度、文本长度和图片数量上限，拒绝未知节点、未知属性和不合法枚举，不接受客户端提供的任意 HTML 或 CSS 作为最终发布内容。

## 主题模型与微信 HTML 渲染

主题由服务端代码内置，包含稳定的 `themeId`、整数 `themeVersion`、展示名称、预览色及各节点样式令牌。稿件和每个历史版本都记录所用主题及版本；主题注册表保留已被稿件版本引用的旧定义，升级主题时新增版本，不原地覆盖旧版本。

首版主题标识固定为：

- `minimal-business`
- `clear-blue`
- `natural-green`
- `warm-lifestyle`
- `elegant-chinese`
- `vibrant-brand`

服务端渲染器是发布 HTML 的唯一权威来源：

1. 校验结构化文档及所有稿件素材归属。
2. 对文本和链接进行转义与协议校验。
3. 按指定主题版本把节点映射为受控标签和内联样式。
4. 图片输出为 `data-weavepress-draft-asset-id` 占位，发布适配器继续负责上传微信素材并替换 URL。
5. 返回确定性的 `contentHtml`；相同文档和主题版本必须生成相同结果。

主题样式不会经过允许任意 `style` 的通用清洗器。所有内联样式只能来自可信的服务端主题定义；用户内容始终作为数据转义。旧 HTML 转换前仍使用现有白名单清洗策略。

## 数据模型

### `drafts`

新增：

- `editor_document JSON NULL`
- `theme_id VARCHAR(64) NOT NULL DEFAULT 'minimal-business'`
- `theme_version INT UNSIGNED NOT NULL DEFAULT 1`

现有 `content_html` 保留，作为服务端生成的当前发布结果，不再是可视编辑器的源数据。

### `draft_versions`

新增同样的 `editor_document`、`theme_id` 和 `theme_version`。每次保存把结构化文档、主题、生成 HTML、标题、作者、摘要和封面作为一个不可拆分版本写入。

### `draft_assets`

新增稿件素材表，核心字段：

- `id`、`draft_id`
- `origin`：`article` 或 `upload`
- `article_asset_id`：来源图片时填写
- `object_key`、`media_type`、`byte_size`、`width`、`height`、`sha256`
- `uploaded_by`、`created_at`

创建稿件或首次进入新版编辑器时，把来源文章中可用图片登记为 `article` 素材记录，但复用原对象存储文件。上传图片登记为 `upload` 记录。正文和封面统一引用 `draft_assets.id`，服务端验证素材属于当前稿件。

同一稿件的 `article_asset_id` 只允许登记一次；`origin=article` 时必须填写该字段，`origin=upload` 时必须为空。

对象键按内容哈希生成，相同文件可复用底层对象，但权限和稿件关联仍分别记录。

## API 变化

### 主题

- `GET /api/wechat-layout/themes`：返回内置主题列表、当前版本和用于前端预览的受控样式令牌，不返回任意可执行 CSS。

### 稿件素材

- `GET /api/drafts/{id}/assets`：返回来源图片和上传图片的统一素材列表及短期媒体地址。
- `POST /api/drafts/{id}/assets`：`multipart/form-data` 上传单张图片，仅 `editing` 状态可调用。

上传只接受实际内容确认为 JPEG、PNG、GIF 或 WebP 的文件。单文件不超过 10 MiB；超过微信正文 1 MiB 限制的图片可以作为封面候选，但不能插入正文，并在界面明确标记。

### 稿件读取与保存

`GET /api/drafts/{id}` 增加：

- `editorDocument`
- `themeId`
- `themeVersion`
- `migrationNeeded`

更新稿件接口改为提交 `editorDocument`、`themeId` 和 `expectedVersion`；客户端不再决定最终 `contentHtml`。服务端校验、渲染并在同一事务内更新稿件、创建版本和审计事件，响应继续返回生成后的 `contentHtml` 与 `previewHtml`。

版本读取和恢复接口返回并恢复结构化文档与主题。旧版本没有结构化数据时，在恢复时完成转换并创建一个新的当前版本，不修改历史记录。

## 旧稿兼容

当 `editor_document` 为空时：

1. 读取接口对现有 `content_html` 做白名单清洗并转换为允许的结构化节点。
2. 返回临时 `editorDocument` 和 `migrationNeeded=true`，读取本身不写数据库。
3. 编辑者首次保存后，结构化数据、默认主题和重新渲染的 HTML 才正式落库并形成新版本。
4. 无法精确转换的受支持文本保留为普通段落；未知结构被丢弃并返回警告。
5. 如果转换无法得到有效正文，原稿保持不变，页面切换到只读兼容预览并提示人工处理，不自动覆盖数据。

## 保存、审核与发布流程

- 编辑过程中不自动创建服务端版本，避免输入一次产生一个版本。
- 点击“保存新版本”才执行服务端校验和确定性渲染。
- `expectedVersion` 不一致返回版本冲突，页面保留本地内容并提示刷新或复制，不覆盖其他版本。
- 提交审核前必须没有未保存修改，并对最近保存版本执行预检。
- 审核、退回和发布状态机保持不变。
- 发布只能使用最近保存且预检通过的 `contentHtml`；客户端即时预览不能直接进入发布队列。
- 发布适配器从 `draft_assets` 解析图片占位，上传正文图片与封面并写入微信公众号草稿箱。

## 权限与安全

- 沿用现有 `draft:view`、`draft:update`、`draft:review` 和 `draft:publish` 权限；素材读取跟随查看权限，上传跟随更新权限。
- 上传接口校验真实 MIME、文件头、尺寸、大小和图片解码结果，不信任扩展名。
- 禁止 SVG、脚本、事件属性、`javascript:` 链接、外部样式表和外链图片。
- 所有素材引用都校验 `draft_id`，防止通过猜测 ID 引用其他稿件素材。
- 媒体预览继续使用现有短期签名地址；私有对象键不直接暴露。
- HTML 渲染只使用可信主题常量，日志不记录正文和上传文件内容。

## 异常处理

- 图片上传失败不改变稿件或编辑器文档；前端保留未保存正文并允许重试。
- 文件格式、大小或微信正文限制不符合要求时返回稳定错误码和用户可读提示。
- 主题不存在或版本不支持时拒绝保存，不静默改用其他主题。
- 素材不存在、未完成或不属于稿件时拒绝保存并定位到对应图片节点。
- 旧稿转换产生非致命丢弃时展示警告；转换失败时保留原稿并禁止覆盖。
- 服务端渲染失败时不更新稿件、不创建半成品版本。
- 发布前仍执行现有确定性预检，微信临时错误继续走现有异步重试逻辑。

## 验收与最小验证

本轮只执行增量功能直接相关的验证：

- Go：结构化文档校验、六套主题确定性渲染、HTML 转义、旧稿转换、素材归属、上传格式/大小限制、版本冲突和发布图片解析。
- 管理端：编辑器文档转换、主题切换、图片属性、未保存判断及对应生产构建。
- 集成：创建或打开稿件、上传图片、插入正文、切换主题、保存新版本、恢复版本、预检并创建微信草稿发布任务。
- 真实浏览器检查三栏布局、窄屏抽屉、六套主题和手机预览。

验收场景：

1. 旧稿打开后能进入可视编辑器，首次保存形成包含结构化数据的新版本。
2. 切换任意主题不会改变正文节点、文字和图片顺序。
3. 原文图片和上传图片均可插入正文或设为封面，越权素材 ID 被拒绝。
4. 图片可拖动排序并设置宽度、居中和说明，预览实时更新。
5. 保存后刷新页面得到相同结构和排版，历史版本能完整恢复。
6. 两个页面同时编辑时，较旧页面保存得到版本冲突且不会覆盖新版本。
7. 非法 HTML、危险链接、未知节点和不合规图片不能进入发布 HTML。
8. 最近保存版本通过预检后可复用现有流程写入微信公众号草稿箱。

## 发布顺序

1. 先发布数据库迁移和兼容读取能力；新字段允许旧稿为空，不批量重写历史内容。
2. 发布 API、Worker 与新版管理端，继续兼容现有已保存 `content_html`。
3. 使用一篇现有稿件完成上传、排版、保存和预检联调。
4. 微信凭据未启用时只验收到发布前检查；启用后才验证写入官方草稿箱，不自动群发。
